# Gaussian Copula Synthetic Data: Fidelity and Utility

A small, reproducible educational project that evaluates the **generation step** of synthetic tabular data. It compares a Gaussian-copula generator against an independent-marginal baseline on a 4-feature dataset with a binary label, scoring both statistical fidelity and downstream utility.

## Problem

Most synthetic-data work focuses on the downstream task (e.g., classifier accuracy) and treats the generated data as a fixed input. This project inverts the question: **how well does the generator itself reproduce the statistical structure of the real data, and does that fidelity translate into practical utility?**

Two generators are compared:

| Generator | What it captures |
|---|---|
| **Gaussian copula** (algorithm) | Per-feature marginals **and** cross-feature correlations via a fitted 5×5 covariance in rank-transformed space |
| **Independent marginals** (baseline) | Per-feature marginals only; all cross-feature correlations are discarded |

## Implementation

### Data (`data.py`)

`make_dataset(seed, n_samples)` draws i.i.d. samples from a fixed latent model:

- **x0, x1** – continuous, standard-normal marginals
- **x2** – discrete, 3 levels (0, 1, 2), obtained by thresholding a latent normal
- **x3** – discrete, 4 levels (0, 1, 2, 3), same mechanism
- **y** – binary label, a noisy logistic function of x0 and x2

Cross-feature correlations are introduced through a shared latent factor with moderate loadings (0.35–0.55), so the copula has genuine structure to recover. The label depends on x0 and x2, giving the downstream logistic-regression task a real signal.

### Experiment (`app.py`)

`run_experiment(seed, n_samples)` performs the following steps:

1. **Generate real data** via `make_dataset`.
2. **Stratified 70/30 train/test split** of the real data (stratified on `y` to prevent class-imbalance leakage). No temporal ordering exists (i.i.d. data).
3. **Fit marginals on the training set only** (no leakage into the test set):
   - x0, x1: Normal(mean, sd)
   - x2, x3, y: empirical CDF (sorted unique values + cumulative counts)
4. **Generate synthetic samples** (size = training-set size) from both generators:
   - *Baseline:* sample each feature and the label independently from its fitted marginal.
   - *Algorithm:* rank-transform all 4 features + label to standard-normal space (average ranks for ties, probit mapping), fit a 5×5 covariance, draw from the multivariate normal, inverse-transform back (Normal inverse for continuous, empirical-CDF inverse for discrete).
5. **Score fidelity** by comparing synthetic samples against the held-out real test set.
6. **Score utility** by training a `LogisticRegression` on the synthetic set and evaluating accuracy on the real test set.

## Architecture

```
data.py          – dataset generation (latent factor model)
app.py           – copula fitting, sampling, fidelity & utility metrics
test_project.py  – pytest tests for data, experiment, and edge cases
main.py          – CLI entry point (host-supplied)
requirements.txt – pinned dependencies
```

The evaluator in `app.py` treats the real data as ground truth and never accesses the generator internals from `data.py`.

## Metrics

| Metric | Direction | Description |
|---|---|---|
| `ks_continuous` | lower is better | Mean two-sample KS statistic over the 2 continuous features (x0, x1) |
| `tv_discrete` | lower is better | Mean total-variation distance over the 2 discrete features (x2, x3) |
| `corr_mae` | lower is better | MAE over the 6 pairwise correlations of the 4 features |
| `utility_algo_acc` | higher is better | LR accuracy: train on copula synthetic, test on real |
| `utility_base_acc` | higher is better | LR accuracy: train on independent-marginal synthetic, test on real |

**No universal superiority is claimed.** The copula is expected to preserve correlations better, but the measured result depends on the seed and sample size. The baseline may win on some metrics for a given configuration.

## Synthetic Dataset Assumptions and Limitations

- Data is **i.i.d.**; no temporal ordering exists.
- The latent model is fixed and known to the generator, but the evaluator treats the real data as the ground truth.
- Discrete features are generated by thresholding a continuous latent variable, which keeps the joint distribution smooth and makes rank-based copula fitting well-defined.
- The label is a noisy logistic function of two features; the other two features are marginally informative only through the shared factor.
- Sample sizes are small (32–256); statistical estimates (KS, TV, correlations) have non-negligible variance at these sizes.

## Reproducibility

- **Python 3.11–3.13** (uses `from __future__ import annotations`; no version-specific syntax).
- All randomness is seeded: `make_dataset(seed)` and `run_experiment(seed)` are deterministic for the same inputs.
- No network access, no external services, no downloaded datasets.
- CPU-only; the demo runs well under 60 seconds and 512 MB.

## Limitations

- **Small sample sizes.** With 32–256 samples, fidelity metrics have high variance. A single run should not be interpreted as a definitive comparison.
- **Fixed latent model.** The data generator is a known factor model. Real-world tabular data may have more complex dependence structures (non-Gaussian copulas, higher-order interactions) that a Gaussian copula cannot capture.
- **Gaussian copula assumption.** The copula assumes a Gaussian dependence structure in rank space. If the true dependence is non-Gaussian (e.g., tail dependence), the generator will be misspecified.
- **No production readiness.** This is an educational project. It does not handle missing values, mixed-type features beyond the fixed 4-feature schema, or large-scale data.
- **Automated tests have limits.** The pytest suite checks interface contracts (shapes, value ranges, seed sensitivity, sample-size propagation, error handling) and basic metric properties. It does not validate statistical correctness of the copula fit, does not test every possible seed, and cannot guarantee that the algorithm outperforms the baseline on any particular metric.
- **No CI workflow or hosted service.** There are no badges, external URLs, or continuous-integration pipelines.
